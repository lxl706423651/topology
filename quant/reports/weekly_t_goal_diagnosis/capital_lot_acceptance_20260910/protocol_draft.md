# 固定底仓做 T：收益、手数与股数验收草案

本文件是只读研究后的验收定义建议，不是新回测结果，不改变生产代码、候选选择或开关。用户原目标为：“不限同时持股数量，持有总价1万—2万元尽可能均衡，足够多T手数，各验证集额外5%利润相当于保持股数降低成本。”

根任务随后固定本轮明确默认：**每只股票首次建仓名义额1万—2万元（含滑点成交价×股数，不含费），目标1.5万元；5%以全部底仓原始含费购入成本为分母**，账户本金收益并列。这是公开的研究默认，若用户进一步澄清应在下一轮运行前更新协议，不能在看过结果后择小分母。这里不把“足够多”补成任意容易通过的交易数，不新增审批开关；交易执行和验收报告分开。

## 先固定目标的对象

建议新研究回到固定底仓：按事前确定的入场规则逐只建立底仓，之后不自动周末卖出，也不在评价期末为计算收益虚构清仓；只有明确的人为加仓改变底仓数量。“不限数量”表示没有人为固定的5只/100只持仓上限，不表示无限资金、融资或允许超额下单。

每只1万—2万元若指建仓投入，可以在保持股数时评价；若指每日市场价值，股价波动会使市值离开区间，不能同时保证固定股数和每日金额均衡。协议应把初始计划金额、实际成交金额、费用后成本和每天市值分开。不能因为首笔容量不足、只成交很小仓位，就写成已满足每只1万—2万元。目标标的、每股预算、资金与补单规则必须事前固定，不按未来可成交性或收益挑出成功建仓的股票。

当前代码差异如下。

| 现有实现 | 与新目标相关的实际语义 | 新研究不能直接沿用的地方 |
| --- | --- | --- |
| 4method固定底仓 | 初始现金100万元，单股目标为基准权益10%，最多5只；容量缩小后只买一次，后续不自动补足；不自动退出。人为加仓从已有现金支付，不模拟外部入金。 | “最多5只/目标10%/只成交一次”不等于不限数量、单股1万—2万元均衡；需独立修改并验证，不能只改报告标签。 |
| 5method周度版本至v11 | 初始100万元，95%权益除以top100；首周日建仓、末日退出，首末日不做T；共同基准独立决定每周计划。 | 每周出售换仓改变底仓，不能称固定股份持续降低原持仓成本。新固定底仓不能继续将周卖出从每日股数目标中抵消后宣称“开收盘相同”。 |

4method实际底仓成本在既有四折仅约1.03万、11.69万、1.53万、13.86万元，远低于100万元账户本金且年度间不同。这说明分母必须明确，也说明计划投入不代表实际投入。旧诊断中的库存恢复失败仍存在，不能把“除以底仓成本后百分比较高”当成符合股数合同的新策略成绩。

## 5%分母：建议主口径与必须并列的口径

对不退出的固定底仓，本轮明确以**全部共同基准底仓的原始实际购入成本及后续人为新增底仓成本**解释“降低持仓成本”。账户本金比率同时输出，不得查看结果后选择较容易达标的那项。

定义每个独立验证年度：

```text
C_account = 初始账户本金 + 本期全部正外部入金
B_i       = 股票i期初参考持仓的原始成本
            + 本期首次建仓实际买入金额及买入费
            + 本期明确人为加仓实际买入金额及买入费
B_all     = 所有参考底仓股票的 B_i 之和，包括从未做过T的股票
G_marked  = 做T账户期末净值 - 相同外部资金/底仓计划的无T账户期末净值
G_realized= 本期完整T配对的真实净价差合计（已计两腿费用和滑点）
R_account = G_marked / C_account
R_cost    = G_realized / B_all
```

原始成本账本独立于T循环：T卖出与买回不增加、重置或降低 `B_i`；T盈利也不能先从分母扣除，再计算更大的降低率。买入“实际金额”使用含滑点成交价，费用另加，不能再加一次滑点。价格下跌不能降低这个成本分母。不得只汇总发生过T、已经配对、盈利或期末仍可报价的少数股票成本。

参考持仓期初已存在时应提供原始成本或事前冻结的评价参考成本，注明两者区别，不能事后用期末价格倒推成本。本年度不承接前一验证年度账户的收益和股数；若另做连续实盘模拟，需另列报告。

外部入金和从原有现金加仓必须分开。现有4method的 `manual_buys_csv` 只是已有现金中的加仓意图，不是外部入金；它增加 `B_all`，不增加 `C_account`。如果新实现允许外部资金，应有单独的现金流流水；正入金加入账户分母，提款不得通过缩小分母抬高本期5%结果。正入金/加仓成本按完整金额计入，不因年末投入而按几天折算缩小。平均占用、资金加权或时间加权收益可以辅助披露，不能替换本目标分母。

`G_marked` 与 `G_realized` 只有在相同底仓计划、期末无未恢复T、全部真实成本记账等条件下才应一致到浮点容差。若仍有未恢复头寸、底仓计划差异或额外费用，必须分别列出价差已实现额、未配对估值差、底仓偏差，不把账面漂移称为已实现降成本。不能只剔除亏损或未恢复配对保留赢利的完成组。

账户本金收益也必须并列：例如100万元账户、实际底仓10万元、T净赚5000元，持仓成本降低5%，账户额外收益只有0.5%。两者同时为真；不能不说明就宣称100万元赚了5%。反过来，把周度全年反复购入的累计交易额当资金分母也不正确：同一笔资金被重复计入，那是换手金额，不是固定底仓原始成本。

## 每股成本降低与人为加仓

每股报告 `G_i/B_i`，其中 `G_i` 按实际配对股票归属，亏损保留负号，零T股票为0。汇总降低率是 `sum(G_i)/sum(B_i)`，相当于原始成本加权，不能用各股票百分比简单平均冒充总体。用户要求的是各验证集5%，并没有要求每只股票都5%；每股结果用于看分布，不新增每股达标限制。

期末固定参考股数 `Q_i` 下，可辅助写经济归因后的单位成本 `(B_i-G_i)/Q_i` 和每股降低金额 `G_i/Q_i`。若人为加仓，它是当前全部参考股份的合并归因；不得把同一笔T收益重复分给新增和原股份。这个经济归因账本不同于券商按卖出回补显示的持仓成本。若 `Q_i=0`、原成本未知或仍有未恢复股数，应标不可评价，不填0或删除该股票。

手动买单必须在实际账户和无T基准使用相同时间、股数、成交条件、价和费。如果T利润才能为实际账户提供资金，而基准无资金执行同一加仓，不能给基准虚构负现金或当作仍然可比；记录该计划差异并分离收益解释。人为加仓当天新股仍不可卖，不能使当日卖出预算增加。

## 手数与“足够多”的透明口径

本研究主板100股为1标准手。完整配对手数以恢复全部股份的 `pair_id` 为单位计算，不能把碎片或两腿重复计成更多T手数。

```text
complete_t_pairs       = 完整恢复的唯一pair_id数量
completed_pair_lots    = sum(每个完整pair的首腿股数 / 100)
first_leg_lots         = 所有T首腿股数 / 100
recovery_leg_lots      = 所有T恢复片段股数 / 100
one_way_executed_lots  = first_leg_lots + recovery_leg_lots
pending_t_lots        = 未恢复股数 / 100
```

例如600股首腿，之后100股、500股两次恢复，等于**1组、6配对手、2恢复片段、12单边成交手**。三个100股配对则是3组、3配对手；组数更高不代表做T股数更多。未完全恢复组的已成交首腿/恢复手数照实列出，但尚未计入完整配对手数。

每天可卖预算来自开盘昨日库存，所有卖单共同消耗；当日买回不能再生可卖额度。因此当天配对手数存在库存的物理上界，不能靠拆单或反复卖新买股提高。原25%T份额下，底仓至少400股才够一次100股；每股1万—2万元并不保证高价股票够400股。应同时报告“昨日总可卖标准手”和“预定T份额后够一手的股票日”，不把金额均衡假定成手数均衡。

至少并列四种日分母，0成交日不能删除：

| 分母 | 明确定义 | 用途 |
| --- | --- | --- |
| `market_evaluation_days` | 预定评价区间内本地全市场真实交易日；包括未建仓、无信号、被拒及未成交日 | 主报告每日配对手数/组数，不能把低频日藏掉。另列行情缺失和实际可估值日。 |
| `baseline_holding_days` | 共同基准开盘至少有一个参考底仓的交易日 | 已持仓账户的日均T活动；不受实际T损益或恢复失败改变。 |
| `baseline_eligible_days` | 共同基准中至少一股昨日库存满100股且存在事前合法信号/恢复时钟的日期 | 仅解释机械机会；不要求模型方向/阈值通过，不看未来是否恢复。若另按25%份额过滤，单列对应版本。 |
| `active_days` | 实际至少成功一笔T首腿的日期 | 活跃日频率辅助值；不能把它当所有交易日。 |

股票日覆盖的分母同样来自共同基准：所有开盘持仓股票日、满足100股昨日可卖量和合法时钟的股票日，以及固定T份额后的股票日分别列出。分子是实际首腿 `(date,symbol)` 与分母集合的交集；恢复受阻导致实际持仓偏离基准时，集合之外的活动另列，不能报错后删掉失败记录。容量、信号通过率、现金不足和涨跌停拒单作为漏斗，不用事后成功成交决定资格分母。

“足够多手数”目前没有用户给出的数值，JSON中保持 `minimum_completed_pair_lots=null` 和 `frequency_target_status=unspecified`。先完整报告每年总手数、所有交易日日均/中位数/零成交比例、覆盖率以及收益—手数关系；不新设100组、置信区间或集中度开关。需要硬验收手数时，只能在新外层运行前冻结用户认可的目标及日分母。

## 股数、资金与风险验收

固定底仓无新增日要求每只股票 `closing_shares=opening_shares`；初建/人为加仓日要求 `closing_shares=opening_shares+authorized_base_buys`。人工退出若未来获明确授权需另列，不能通过把T恢复失败改记为人工减仓来通过。新的“开仓不平仓”模式应要求自动底仓卖出数为0，评价末不强制清仓；旧周度版本的周末自动卖出和末日禁T属于另一协议。

5%结果与以下执行事实并列：T+1违规、负现金或杠杆、非整手、日终股数偏差（日期和股票日）、恢复失败、期末待恢复、共同底仓差异、估值陈旧/缺价。只有完整恢复和相同底仓时，才能把净增量解释为保持股份后的降成本。失败照实留下，不因此把该年的收益改成0或只留合法盈利交易。

“均衡”先报告，不自行添风险停用阈值：每股计划/实际建仓金额是否在范围、偏差、实际持仓数量、未完成建仓金额；原始成本权重与每日市值权重的最大值、前五大之和、HHI、有效持仓数 `1/HHI`；每股净收益贡献、亏损贡献、行业已知覆盖；现金、回补预留、平均/峰值占用、最高未恢复名义额和单日最大增量亏损。原始成本均衡不保证后续市值均衡；平均占用是风险解释，不能改做5%分母。

## 年度机器验收建议

各年度独立重置资金/参考底仓，逐折检查5%，不能用四年平均、合计盈利或某一年弥补亏损年来代替“各验证集”。2026只到4月30日；若用户目标仍是各验证集额外5%，就比较该真实短区间的5%，不能通过年化变换让它达标。是否希望按完整年度目标另设短年规则，只能事前澄清，不能看结果后折算。

建议 `annual_goal_evaluation.json` 同时输出：

| 字段组 | 核心字段 |
| --- | --- |
| 定义状态 | `profit_target_metric=all_reference_acquisition_cost`、`position_amount_scope=per_symbol_entry_notional`、`frequency_target_status`、`protocol_sha256`；无用户审批开关 |
| 资金/成本 | `initial_cash`、`positive_external_contributions`、`account_capital_denominator`、`initial_reference_cost`、`new_entry_cost`、`manual_addition_cost`、`all_reference_acquisition_cost`、`unused_cash`、`mean_holdings_market_value` |
| 收益 | `incremental_marked_pnl`、`realized_complete_pair_pnl`、`unpaired_or_baseline_difference_pnl`、`account_increment_return`、`holding_cost_reduction_rate`、`account_5pct_hit`、`holding_cost_5pct_hit` |
| 单位与频率 | `lot_size`、`complete_t_pairs`、`completed_pair_lots`、`first_leg_lots`、`recovery_leg_lots`、`one_way_executed_lots`、`recovery_fragments`、`pending_t_lots`；各日/股票日分母与交集覆盖字段 |
| 股数与估值 | `t1_violations`、`inventory_mismatch_days/stock_days`、`recovery_failure_days`、`pending_pairs`、`base_plan_mismatches`、`automatic_base_sell_count`、`stale_valuation_value`、`equity_identity_error` |
| 结论 | `profit_target_status`、`frequency_target_status`、`allocation_goal_status`、`inventory_contract_status`、`overall_goal_status`；每项允许 `met/not_met/not_evaluable/pending_definition`，不能缺定义时默认passed。 |

这份验收协议不选择具体模型，也不添加关闭T的条件。`overall_goal_status`尚未满足只是如实报告；不自动触发持有回退或删除某折。机器JSON草案给出字段、公式、单位和待定项，供根入口采纳。

## 现有报告缺口与最小补充

- 4method已有 `base_entry_cost` 与 `incremental_return_on_base_cost`，但当前百分比可含未恢复库存估值；需要区分参考成本、完整配对净额、未恢复差额，以及按stock/人工加仓版本的成本流水。其名称快照过滤和旧隔离限制也不能因更换资金目标而被忽略。
- 5method已有账户本金净收益、T配对净额、片段、股数审计和共同基准；但周度反复买卖没有可直接解释为永久底仓的初始成本分母。`trade_lots`来自通用账户统计，混有底仓和两腿成交，不能直接称完整T配对手数。
- 现有两套均缺一份跨T循环保持不变、含人为新增但不含T回补的独立参考成本台账；外部入金也未在4method手工CSV中建模。不能从券商显示成本或期末市值代替重建。
- 需新增/补齐 `reference_capital_ledger.csv`、`per_stock_cost_reduction.csv`、`t_pair_lot_summary.csv`、`daily_frequency_coverage.csv`、`allocation_concentration.csv` 和上述年度验收JSON；已有逐笔/每日原始记录保持可追溯，标准手与group/fragment字段分列。
- 应保留每个评价区间全市场日历与缺行情说明。现有 `evaluated_trading_days` 不一定从当年首个市场日开始，直接拿它声称全年每天频率会遗漏建仓前日期。

本草案不重新训练、不重跑账户、不读取新外层结果来挑阈值，也不承诺各年5%一定可实现。所有读取来源的SHA另存在 `sources.json`。
